📖 本地部署教程

从零开始，在自己的电脑上跑起开源大模型。按难度选择：Ollama（最简单）→ LM Studio（图形界面）→ llama.cpp（进阶）→ vLLM（服务器级）

1️⃣ Ollama — 一行命令跑大模型 最简单

Ollama 是目前最流行的本地模型管理工具，自动处理量化、显存分配、上下文等，一条命令即可运行。支持 Windows / macOS / Linux，全中文界面友好。

① 安装

  1. 打开官网 ollama.com/download，下载 Windows 安装包（约 700MB，含运行时）
  2. 双击安装，装完后右下角托盘会出现 Ollama 图标

② 运行模型

打开终端（Win+R 输入 cmd 回车），输入：

ollama run qwen3:8b

首次运行会自动下载模型（几 GB，视网速而定），之后就进入聊天界面，直接输入问题即可。退出用 /bye。

③ 常用命令

ollama list                      # 查看已下载的模型
ollama pull qwen3:8b             # 只下载不运行
ollama run deepseek-r1:7b        # 运行 DeepSeek 推理模型
ollama rm qwen3:8b               # 删除模型释放磁盘
ollama ps                        # 查看当前加载的模型与显存占用

④ 修改模型存放位置（可选，默认在 C 盘）

设置环境变量 OLLAMA_MODELS 指向新目录（如 D:\ollama-models），然后重启 Ollama。

⑤ 集成到桌面/API

  • Ollama 自带 OpenAI 兼容 API：http://localhost:11434/v1，任何支持 OpenAI 的客户端（ChatBox、NextChat、Cherry Studio、Dify 等）填这个地址即可接入
  • 推荐搭配图形界面 ChatBox 或 Cherry Studio，体验接近 ChatGPT

💡 检测站里每个模型行都有一个「Ollama」按钮，点击即可复制对应的 ollama pull 命令。

2️⃣ LM Studio — 全图形界面 最简单

完全图形化操作，无需命令行，内置模型搜索下载，直接下载 GGUF 文件即可运行，适合新手。

  1. 到 lmstudio.ai 下载安装
  2. 打开后在「搜索」页查找模型（如 Qwen3 8B），选择 Q4_K_M 量化版本下载
  3. 回到「聊天」页，选择刚下载的模型，即可对话
  4. 设置里可开启「本地 API 服务器」，供其他程序调用

⚠️ LM Studio 内置下载走 HuggingFace，国内网络可能较慢，可在设置里改用 ModelScope 镜像，或直接到 ModelScope 下载 GGUF 文件后拖入。

3️⃣ llama.cpp — 自由与性能 进阶

llama.cpp 是 GGUF 格式的源头项目，纯 C/C++ 实现，CPU 效率最高，支持 NVIDIA/AMD/Intel 显卡加速（CUDA/Vulkan/Metal）。

① 获取可执行文件

Windows 用户直接到 GitHub Releases 下载 llama-bXXXX-bin-win-cuda-cu12.4-x64.zip（CUDA 版）或 ...-win-avx2-x64.zip（纯 CPU 版），解压即可，无需编译。

② 下载 GGUF 模型

从 HuggingFace 下载（如 Qwen3-8B-Instruct-GGUF），选 Qwen3-8B-Instruct-Q4_K_M.gguf。

💡 国内用户建议到 ModelScope 搜索同名 GGUF 仓库下载，速度快得多。

③ 运行

llama-cli -m Qwen3-8B-Instruct-Q4_K_M.gguf -n 512 -c 8192
# -n 生成的最大 token 数，-c 上下文长度

GPU 版会自动检测并使用显卡（-ngl 999 强制全部层进显存）。

④ 常用工具

llama-server -m model.gguf --port 8080   # 启动 OpenAI 兼容 API 服务
llama-bench -m model.gguf                 # 实测本机 tok/s 速度
llama-gguf-split -m model.gguf --split-max-size 4G  # 拆分大文件

配合 llama-bench 可以实测你的机器真实速度，和本站估算值对照。

4️⃣ vLLM — 服务器级高吞吐 高阶

vLLM 是工业级推理框架，适合大显存（多卡）机器、API 服务、并发多用户场景。对单机个人使用通常不如 Ollama 方便。

# 需要 Python 3.9+ 和 NVIDIA GPU（CUDA）
pip install vllm
vllm serve Qwen/Qwen2.5-7B-Instruct --gpu-memory-utilization 0.9

启动后提供 OpenAI 兼容 API：http://localhost:8000/v1。常用参数：--max-model-len 32768（上下文长度）、--tensor-parallel-size 2（双卡并行）。

⚠️ vLLM 一般需要 24GB 以上显存才划算，且目前主要支持 NVIDIA（AMD 需 ROCm 构建）。低配机器请优先 Ollama。

5️⃣ 量化是什么？为什么 Q4 能跑 Q8 跑不了？

大模型的权重是浮点数。量化就是把权重从 16 位浮点压缩到更少的位数，文件变小、占用显存内存变小、速度变快，代价是轻微精度损失。

  • Q4_K_M（≈4.5 bit/参数）：体积约为 FP16 的 1/4，精度损失很小，本地部署首选
  • Q8_0（8 bit）：几乎无损，体积约为 FP16 的一半
  • FP16：原始精度，体积最大，一般只有大显存显卡才用
  • IQ4_XS / Q3_K_M：更激进压缩，牺牲更多精度换体积，8GB 内存的老机器可用

规律：模型文件能塞进显存就用 GPU，塞不进就部分 offload 或纯 CPU。MoE 模型例外——文件大但激活参数少，CPU 跑也不慢。

6️⃣ 常见问题

Q1：提示「显存不足 / CUDA out of memory」怎么办？

  • 换更小的量化：Q8_0 → Q4_K_M → Q4_0 / IQ4_XS
  • 换更小的模型：8B → 4B → 1.5B
  • 减少上下文长度（-c 8192 → 4096），KV cache 也占显存
  • Ollama 中退出其他模型再运行（ollama ps 查看占用）

Q2：CPU 推理太慢怎么办？

  • 确认内存是双通道且跑在最高频率（CPU 推理吃内存带宽）
  • 确认已用 AVX2/AVX512 构建（llama.cpp 的 avx2 版比通用版快 30%+）
  • 选 MoE 模型（Qwen3-30B-A3B 在 CPU 上接近 7B 的速度）
  • 降低上下文长度与批处理大小

Q3：下载慢 / 连不上 HuggingFace？

  • 国内优先用 ModelScope（阿里，速度快）
  • Ollama 可设置镜像：环境变量 OLLAMA_HOST 无关，镜像见社区方案（如 hf-mirror.com：export HF_ENDPOINT=https://hf-mirror.com 适用于 HF 工具）

Q4：模型回答是英文 / 中文不好？

选中文优化模型：Qwen（通义千问）、GLM（智谱）、DeepSeek 系列中文支持最好。

Q5：8GB 内存的老电脑能玩吗？

能。Qwen3-0.6B / Qwen3-1.7B / Llama-3.2-1B（Q4）都只要 1GB 左右内存，速度也快；再往上 3B、4B 也能勉强跑，但建议 16GB 内存起步体验更好。

Q6：本站估算的速度准吗？

误差一般在 ±30% 内，用于横向对比足够。想知道精确值，用 llama.cpp 的 llama-bench 实测即可。

7️⃣ 资源汇总

  • Ollama 模型库 — 所有支持一行安装的模型
  • HuggingFace — 全球最大模型仓库（GGUF 官方/社区版）
  • ModelScope 魔搭 — 阿里模型仓库，国内速度快
  • llama.cpp — GGUF 推理引擎源码
  • vLLM — 高吞吐推理框架
  • LM Studio — 图形化推理客户端
  • Cherry Studio — 桌面 AI 客户端（支持本地 Ollama）
