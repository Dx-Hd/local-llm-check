# Local LLM Check 功能与 UI 设计

## 目标

保留现有本地大模型配置检测、模型对比、速度估算和教程功能，新增用户主动检测入口、公开模型目录更新和更完整的 GPU 手动修正选择器，并统一首页与教程页的视觉层次。

## 交互范围

- 页面加载时不再自动触发硬件检测；用户点击“检测本机配置”后开始检测。
- 检测结果按“已读取 / 粗略估算 / 无法读取 / 手动修正”区分，不伪造浏览器无法提供的数据。
- 手动 GPU 选择器按 NVIDIA、AMD、Intel、Apple Silicon、核显分组，补充常见桌面、移动与专业型号；保留“其他型号”与自定义显存兜底。
- 模型目录提供“更新模型库”入口，显示来源、成功更新时间和失败状态；内置模型始终作为离线 fallback。

## 数据同步

- Hugging Face：调用公开 `/api/models`，筛选 text-generation、GGUF 等适合本地部署的模型。
- ModelScope：调用公开 OpenAPI `/openapi/v1/models`，筛选 text-generation 或兼容本地部署的模型。
- GitHub：调用公开 REST `/search/repositories`，按本地 LLM / GGUF / llama.cpp 等关键词查询仓库。
- 返回数据统一为轻量目录条目，不覆盖原有精确估算字段；没有可靠体积或参数量时标记为“待核对”，不参与精确速度排序。
- 使用 localStorage 缓存结果和更新时间；任何单一来源失败都只显示该来源失败，继续显示内置/缓存数据。

## UI 方向

- 保留深色科技主题，但强化“检测入口”作为首屏主任务。
- 使用冷蓝作为动作色、青绿色作为已检测状态、橙色作为来源/警告色；减少无意义渐变，增加状态标签和数据层级。
- 所有新增按钮有键盘焦点、禁用态和 `prefers-reduced-motion` 支持。
- 维持 720px 以下移动端可用，表格继续横向滚动，GPU 选择器可搜索。

## 验收标准

1. 不点击检测按钮时，页面不显示检测后的配置和推荐结果。
2. 点击检测按钮后能显示现有可读取字段；无法读取项有明确文案。
3. 手动选择已收录 GPU 后能自动显示对应显存；自定义型号可填写显存并参与估算。
4. 点击更新模型库时，至少能独立处理三个来源的成功、失败和缓存 fallback。
5. 原有筛选、排序、推荐、图表、复制 Ollama 命令和教程链接保持可用。
6. Node 静态测试、HTML/JS 语法检查和浏览器 smoke test 通过。
